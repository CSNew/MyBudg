# ความปลอดภัยของข้อมูลใน MyBudg

## ข้อมูลที่เข้ารหัสก่อนบันทึกลงฐานข้อมูล

AES-256-GCM (รูปแบบ `v1:{keyId}:{nonce}:{cipher}:{tag}`) ผ่าน EF Core value converter:
จำนวนเงิน, โน้ตรายการ, ชื่อ/ต้นทุน/มูลค่าการลงทุน, ชื่อ/ยอดเป้าหมายออม, รายได้ต่อเดือน, วงเงินงบรายหมวด

**ไม่เข้ารหัส** (ต้องใช้ query/เรียงลำดับ): อีเมลและข้อมูลบัญชี Identity, UserId, วันที่ของรายการ, ประเภท (รายรับ/รายจ่าย),
รหัสหมวด, ชื่อ/สี/ไอคอนหมวด, ประเภทการลงทุนและวันที่ซื้อ, วันที่เป้าหมายออม
ผู้ที่เข้าถึงฐานข้อมูลได้จึงเห็นข้อมูลเหล่านี้ แต่ไม่เห็นตัวเลขเงินและข้อความ

**Data Protection key ring** (ใช้เซ็น cookie ล็อกอินและ antiforgery) เก็บในตาราง `DataProtectionKeys`
และถูกเข้ารหัสด้วยคีย์ของแอปเช่นกัน — ฐานข้อมูลรั่วอย่างเดียวจึงปลอม cookie ล็อกอินไม่ได้

## คีย์เข้ารหัส

คีย์ = Base64 ของ 32 ไบต์ เก็บนอก repo และนอกฐานข้อมูลเท่านั้น

```bash
openssl rand -base64 32
export Encryption__CurrentKeyId=k1
export Encryption__Keys__k1=<คีย์ที่สร้าง>
```

- **Development**: ถ้าไม่ตั้งค่า ระบบสร้างคีย์ทดลองที่ `App_Data/dev-encryption.key` (ไม่ถูก commit)
- **Production**: ไม่ตั้งค่า = แอปไม่เริ่มทำงาน
- **Rotate**: เพิ่มคีย์ใหม่ (`k2`) แล้วเปลี่ยน `Encryption__CurrentKeyId` — ข้อมูลเก่ายังอ่านได้ด้วยคีย์เดิม
  **ห้ามลบคีย์เก่าและห้ามทำคีย์หาย** ถ้าคีย์หาย ข้อมูลที่เข้ารหัสด้วยคีย์นั้นกู้คืนไม่ได้
  (ควรสำรองคีย์ไว้ในที่ปลอดภัยแยกจากที่รันแอป เช่น password manager ของทีม)
- ถ้าเปลี่ยนคีย์ปัจจุบันเป็นคีย์ใหม่โดยไม่เก็บคีย์เดิมไว้ key ring ของ Data Protection จะอ่านไม่ได้ → ผู้ใช้ทุกคนถูกบังคับล็อกอินใหม่
  (ปลอดภัย แต่ข้อมูลที่เข้ารหัสด้วยคีย์เดิมจะอ่านไม่ได้)

## การเข้าถึง

- รหัสผ่านอย่างน้อย 12 ตัว, lockout 5 ครั้ง/15 นาที, rate limit การ POST หน้า Login/Register ต่อ IP
- ข้อมูลทุกตารางผูกกับ `UserId` และกรองอัตโนมัติ (ไม่มีผู้ใช้ = ไม่เห็นอะไรเลย)
- การสมัครสมาชิก: `Registration__Mode` = `Closed` (ค่าเริ่มต้น) | `InviteOnly` (ต้องมี `Registration__InviteCode`) | `Open`
  ถ้าลืมตั้งค่าจะปิดรับสมัคร (Development เปิดไว้เพื่อทดลอง)

## ข้อจำกัดที่ยังมี (ดูแผนงานต่อ)

- ยังไม่มี 2FA, อีเมลยืนยัน/รีเซ็ตรหัสผ่าน, การตรวจรหัสผ่านที่เคยรั่ว, audit log
- คีย์เข้ารหัสอยู่ใน environment ของโฮสต์ (ยังไม่ใช้ Key Vault/KMS แบบ envelope encryption)
- ยังไม่ครบข้อกำหนด PDPA (นโยบายความเป็นส่วนตัว ความยินยอม ลบบัญชี/ส่งออกข้อมูล)
